# invariant.md -- CHAOS-6036 (design; each code PR in the stack gets its own)

## Invariant, relative to main 7ece7cc0
For every unit the gate evaluates, in `go` mode the estimator returns exactly the list of (bucket key, estimated units, confidence, route family, notes) that Python's `/dispatch-budget-estimate` returns for that unit at that moment, so every admit, defer and consumption decision equals main's; the only differences from main are that the network failure classes do not exist and a whole-chunk database read error fails the pass instead of failing open. In `python` and `shadow` modes behaviour is byte-identical to main; shadow adds counters and logs only, on its own database connection, so it cannot poison the gate's transaction. One named exception, E1: PagerDuty units in `oauth` or `client_credentials` mode whose Python hydration fails get a Go estimate where Python returned none; this can change a decision (cooldown match defers the unit) and is pending a lead ruling on that corrected basis.

- Time: same pass; next pass (active units are re-estimated by C every pass); credential rotated between passes; run-stamped vs NULL-stamped run (fallback to the mutable integration credential); the two reads in shadow taken at different instants.
- Plane below: Postgres reads by the Domain role, Fernet key present in the dispatch process, Python API availability.
