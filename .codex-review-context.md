Repairs `daily_metrics_runs` rows whose generation is `redrive:<nonce>`. The current writer (`finalizeRedriveGeneration`, internal/jobs/metrics/daily/redrive.go) appends `#finalize-redrive:<nonce>` to the run's generation and never replaces it, so no code path writes `redrive:<nonce>`.

New verb `dho workers metrics generation-repair --org --from --to [--dry-run]`:
- A run id is `uuid5(org|day|generation)` (`newRun`), so the original generation is PROVEN, not guessed: every generation family the runner mints is tried and a candidate is accepted only when it hashes to the row's own id: `fixed-schedule:daily_metrics_fanout:<RFC3339 second>` (36h before to 5m after `created_at`), `post-sync:<id of an org sync_run created up to 14 days before>`, `touched-drain:<n|e>:<id of an org daily run>`, `manual-daily:` without repo list or rerun tag. Output carries `by_family`.
- Rows with any other original generation (post-sync, manual) are counted as `not_provable` and left alone. Rows still being redriven (not succeeded/succeeded, or an open redrive event) are `not_settled` and left alone.
- Write is a compare-and-set on the old generation: idempotent, a second pass repairs nothing. Each row logs at Warn with old and new value; the pass logs counts. Audited under the existing `metrics.finalize_redrive` action (no new audit action, no migration).
- A restored fan-out row also gets `full_org=true`, the value migration 0148 gave every fan-out row; other families keep `full_org` as is.

## TEST-EVIDENCE

- Integration (real migrated Postgres): `TestRepairLegacyRedriveGenerationsRestoresOnlyProvenFanoutRuns` — damaged fan-out restored and `coveringRunForDay` finds it afterwards (nothing before); post-sync, in-flight, open-event and other-org rows untouched; dry run writes nothing; second pass repairs nothing.
- Manual runs with a repo list or rerun tag, and post-sync of a sync run older than 14 days, stay `not_provable`.
- `TestEveryDirectWriteVerbIsAuditedBeforeItWrites` covers the new verb.
