## What this change makes observable

It is intended to expose an optional Atlassian Teams failure through a WARN, a `native_failed_nonfatal` dispatch outcome, and a named degraded entry in the discovery ledger and `sync_runs.result`. It also gives credential refusals fixed reasons and makes the strict CLI verb fail.

An Info-only view would miss a regression that drops the WARN and the run-result entry: units can still succeed, leaving the run looking clean. It would also miss the credential leak reproduced below, which appears in the WARN and degraded detail.

## Findings

1. **P1 — The gateway can echo a Jira credential into logs and stored detail.** In [jira_atlassian_teams_collector.go](/var/lib/oci-cache/lane-scratch/gwc-pycallers-7132-r1/codex-review-worktree-gwc-pycallers-7132-5da6a9ba-20261001T063629-Fa7N4S/internal/workerservice/jira_atlassian_teams_collector.go:128), the warning logs the raw error; at [line 152](/var/lib/oci-cache/lane-scratch/gwc-pycallers-7132-r1/codex-review-worktree-gwc-pycallers-7132-5da6a9ba-20261001T063629-Fa7N4S/internal/workerservice/jira_atlassian_teams_collector.go:152), the same error text becomes `DegradedLeg.Detail`. I ran the real Atlassian GraphQL client against a TLS test server that returned the test credential as its GraphQL error message:

   ```text
   REPRO graphql_error_token warning_has_token=true degraded_detail_has_token=true reason="unclassified"
   --- FAIL: TestReviewGraphQLErrorEchoReachesWarnAndDegradedDetail
   ```

   A separate executed `Discover` path check confirmed the sanitizer leaves a bare credential in the degraded payload:

   ```text
   REPRO discovery_ledger_payload detail_has_test_credential=true outcome=native_degraded leg=jira_atlassian_teams
   --- FAIL: TestReviewDiscoveryDegradedPayloadRetainsBareCredentialEcho
   ```

   The token was generated in an environment variable and was not printed.

2. **P1 — Post-sync dispatch drops the degraded entry from the run result.** At [team_catalog_clients.go:601](/var/lib/oci-cache/lane-scratch/gwc-pycallers-7132-r1/codex-review-worktree-gwc-pycallers-7132-5da6a9ba-20261001T063629-Fa7N4S/internal/workerservice/team_catalog_clients.go:601), a returned degraded leg only records a metric outcome.   
   ```text
   REPRO post_sync_degraded status=success result={"failed_units": 0, "completed_units": 14} dispatch_outcome=native_failed_nonfatal
   --- FAIL: TestReviewPostSyncDegradedLegLeavesRunResultClean
   ```

   The dispatch outcome signals a failure, but `sync_runs.result` stays unchanged and contains no degraded entry.
